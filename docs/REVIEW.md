# Cursor 版本审查与本轮修复

审查对象为原始 `index.html`、`css/game.css` 与 `js/game.js`。以下问题均已在本轮调整。

| 发现 | 对体验的影响 | 修改 |
| --- | --- | --- |
| 下落动画 820ms，而下一颗和胜利判定在 620ms 后触发 | 最后一颗尚未落地就显示成功 | 等待实际动画结束，落稳后计数、激活下一颗或判胜 |
| 整个果实层都在篮子 SVG 上方 | 果实像贴在篮外或悬空 | 拆分篮后壁与前壁，果实处于两者之间 |
| 堆叠行距只有画面高的 5.6% | 同尺寸的果实严重交叠成团 | 按新画布和果实尺寸重新计算行距和错位，保持尺寸不变 |
| 锁定动画时仍缓存键盘输入 | 下一颗未亮便可能被摘取或误判 | 动画期间忽略输入，亮起后再接受 |
| 果实有表情、绿色花萼，黄色圆形字母底遮住果皮 | 难以识别为正常红石榴 | 饱满红果身、红棕花萼、细斑与暖色高光，黄色光晕置于果实外围 |
| 正方形场景被下方控件挤小 | iPad 横屏时果实不突出 | 1000×760 场景，横屏提示侧置、竖屏提示下置 |
| 背景只有平滑山丘，落叶形状单一 | 古风庭院和秋叶辨识度不足 | 灰瓦院门、青石地、远山、棕色树纹和带侧脉的彩叶 |
| 直接读取和写入 localStorage | 存储被禁用时可能无法进入游戏 | 存储失败时继续游戏，仅不记忆静音设置 |
| 全局 Enter 处理早于重复键和焦点判断 | 可能抢占按钮操作、长按切关 | 过滤长按、输入法组合、编辑框和按钮原生操作 |

## 验证范围

- JavaScript 语法检查。
- 七项自动测试：八局完整流程、树上槽位间距、篮内堆叠和等尺寸、落稳后判胜、旧动画不干扰重开、减少动态、存储和键盘边界。
- 桌面浏览器真实按键事件采摘，检查入篮画面与成功提示。
- 按 iPad 常见横竖屏尺寸检查布局；真实 iPad、实体键盘和触摸仍需实机试玩。

这一轮保留原有八局、点击操作及声音开关，主要针对小小创作者的美术反馈和直接影响落果体验的问题迭代。
